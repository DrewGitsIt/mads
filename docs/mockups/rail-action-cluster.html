The one real cost is that it can't be CSS-only. .rail is overflow-y: auto, and a scroll container clips both axes — an absolute child cannot escape sideways. The cluster has to be position: fixed with its top and left computed from the row's rect, which is exactly what LinkOptionsMenu already does through Popover's style prop (commit 2266faa), so the pattern and its helper already exist in this file's neighbours.

Three things that have to be right. (1) The pointer must never cross dead space between card and cluster or :hover drops and the cluster flickers — hence the 8px transparent bridge in the cluster's own padding-left rather than a margin. (2) Fixed coordinates go stale on rail scroll and window resize; reposition on both, or close on scroll. (3) The cluster stays a DOM child of the row so :hover, :focus-within and tab order all still work — only its painting moves.

aside Why the cards are too tall two findings from the screenshot, not part of this change

The blank lines in the rail are not slack in the design — they are a bug. Every card in the screenshot is a current_dir session in the single workspace mads, so none of them should carry a context line at all. They all carry one anyway, and one of them renders a bare dot.

LineHeightRendering in the screenshot
name17pxthe session name
status15 + 4px"Ready", "Sleeping · wakes on send"
context13 + 4pxblank, or a lone "." — see below
meta~15 + 4px"1 running", LEADER, TOOLS ON RESTART
summary14 + 4pxpresent on some
stamps14 + 4pxreserved always, painted on hover/selection
card87–120pxof which 17px is a line that renders nothing

1 · the workspace lookup never hits. railLabels.workspaceFactsByName keys facts by Workspace.name and looks them up with session.workspace. But the live record holds an id — every session in the screenshot has workspace: "wsp_b8439a998b38a07f" against a workspace named mads. So facts.get() always misses, primaryRepo is never known, and the "this cwd is just the workspace's repo, don't label it" test can never fire. Same assumption in useSessionWorkspace.ts:27 and ConversationHeader.tsx:130, which would print the raw id.

2 · and so cwd is always labelled, as ".". A current_dir session stores cwd: "."; displayPath(".") returns "." unchanged. That is the stray dot on the third card, and the leading dot in "· mads-bug-investigator" on the second. Fix the lookup and these cards carry no context line at all — which, since its height is deliberately reserved, is 17px back on every card before anything is redesigned.
