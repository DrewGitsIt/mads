Pipeline runs, inside the Tasks tab (v2)

The Tasks tab has two views of the same run. List draws the template as a metro line with tasks riding it, above an editable task list. Graph is the dependency graph with semantic zoom. Both share one run bar and one lens for zooming into a task. Click any task to zoom in, and press Esc to close a lens, a focus view, or a popover. In the Plan phase, the template picker and the per-task include boxes work, and the pre-flight warnings update as you change them.

What changed from v1

  • The run bar shows only the run: view toggle, run dropdown, template, status, elapsed time, and Cancel. No cost, no progress bar, no counts written out. Pre-flight shows a single warning line, and only when something needs your attention.
  • The run dropdown is the run history. Picking a past run loads its final state. Picking the live run follows it live. In Plan, the dropdown reads New run.
  • Blocked is called Blocked. "Needs review" is reserved for a future human-gate stage. That status already exists (needs_review), but no stage type produces it yet.
  • The metro line replaces per-task stage tracks in the list. List rows are grouped Blocked → Running → Queued → Done → Not in this run. Any stack of more than 3 tokens on a station collapses to +N, and clicking it opens a filterable list.
  • No made-up words. Stations read Queued / Ready and Done. A blocked task sits under the stage that blocked it, labelled Blocked.
  • Past attempts: when a stage ran more than once, attempt N ▾ becomes a dropdown that switches between that stage's attempt logs.

Backend this design needs

  • Leave tasks out of a run: POST /pipelines accepts exclude_task_ids, and the engine's runnable() skips them. Tasks that depend on a left-out task are reported as skipped, the same way an unsatisfiable dependency is today.
  • Logs for a given run and attempt: …/output and …/turns accept ?run=&stage=&attempt=. The files already exist as runs/<session>/<run>/<task>/<stage>-attempt-<n>.log. Today both endpoints only ever read the latest run.
  • Cancel after a reload: put run_id on pipeline.started (or add POST /sessions/{id}/pipeline/cancel). The run fold already replays that event, so a reloaded page gets the id back.
  • The template picker: list Library templates and default to the workspace's bound template, instead of the hard-coded default-implementation.
