B Tray docked above the composer

A one-line tray sits just above the composer, like an "N new messages" bar, and is visible no matter how far you've scrolled. Clicking it opens a short scrolling list with the actions in a footer. The stream itself doesn't change until the updates are delivered.

  • Always visible, and it sits right next to the thing that also flushes the backlog (sending a message).
  • Doesn't touch stream rendering, the runway, ⌘F or the turn strip while the updates are waiting.
  • Takes composer space; it competes with whatever else docks there (queued sends, the permission bar).
  • The updates aren't in the history until delivered, so discarded ones need a separate record (shown in the stream).

C Held updates go with your next message (revised ×2)

The held updates are listed in the conversation like A, as D's compact rows: grouped by session, click to expand. They're attached to your next message automatically. There are only two outcomes: they go to the agent, or you discard them. To send them, either send a message (they ride along in the same turn) or use Send updates only (the old "just send these"). To stop them, discard one row with its ×, or all of them. There's no "hold them back for later".

  • Matches today's behavior (waking the session delivers everything), but now visible and editable before it happens.
  • One turn for "updates + your question", and the history shows exactly which updates the agent saw with which message.
  • No backlog that quietly grows: anything held is either about to go or gets discarded.
  • Discarding is the only way to keep an update out, so it has to be cheap and reversible (undo toast), and it stays auditable.

Message SOM-DST Classifier Primer↑
Rules this version assumes.
  • Every held update is attached to the next message by default. The only way to keep one out is to discard it.
  • Any send delivers whatever is still held: your message, Send updates only, or the "Wake now" warm-up (it sends them as one turn, like today's flush).
  • × on a row discards that update; × on the composer chip discards everything still held. Both offer Undo, and both leave a "discarded by you" record you can expand and find with ⌘F.
  • Updates that arrive while you're drafting join the list and the chip automatically.
  • Signal wakes (blocked, crash, needs_review, permission) deliver everything held, with no human in the loop, exactly as today.

D Triage list (pick which to deliver)

Like A, but built for picking: compact one-line rows with checkboxes, grouped by session, and a footer that counts what you've picked ("Deliver 3 · Discard 2"). Clicking a row expands it to the full digest. This works best when backlogs get long (a leader asleep overnight under several busy subjects).

  • One action handles a mixed decision; scales to 20+ updates.
  • Rows are one line each, so the block stays short.
  • Checkboxes in a conversation are a new pattern for mads.
  • Overkill for the usual 1–3 updates; it could start as A and switch to D past some count.
