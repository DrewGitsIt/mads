per-file strategy: applies on retry
Retry runs the resolve agent in the task's worktree with your guidance + both task descriptions, then the full gate. Destructive choices confirm and keep a backup branch. Resolution lands as a normal serialized merge — post-merge verify still runs.
After “Retry with agent”: this strip shows live stage progress (resolve → build → test → merge) with the same event stream the Pipeline board uses.

Flow notes

1 · Conflicts enter the queue only after the free layers fail (git auto-merge, then merge_resolve). 2 · "Agent resolving" cards are watchable but need no action; "needs you" cards block that task only — the run continues elsewhere. 3 · "Open worktree in a session" spawns a normal interactive session cwd'd in the task worktree — full tooling, no special mode. 4 · Everything here is also a task-note trail: each retry/choice posts to the task's notes for the retro.
