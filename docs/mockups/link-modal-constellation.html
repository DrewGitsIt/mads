Interactions

  1. Chain on any card centers the modal on that session. There's no separate "opened from" state: a subordinate's chain shows its leader above it.
  2. Click a node to re-center (breadcrumbs let you step back). ▲2 ▼1 on a node counts its links outside this view, so you can tell there's more to explore.
  3. Click a line's badge to edit that link: Leads or Monitors, Follow, Signals or Muted, swap direction, remove. Leads is disabled with the reason shown when the subordinate already has a leader.
  4. Rail clicks add or select. Clicking a session not linked to the centered one adds it below as Leads with Signals (Monitors if it already has a leader), with its editor already open. There's no global default to configure. Clicking a session that's already linked opens its line's editor.
  5. One draft, one Save. Edits stay pending (amber dot on the badge) until Save. Esc, Cancel, × or a click on the blurred pane asks before discarding anything.
  6. No mute mark in the rail. Mute shows only in the modal.

Rules the modal enforces (from store/links.go)

  1. At most one leader per session; any number of monitors.
  2. One link per pair, so no A→B and B→A together. Swap direction flips the existing link instead.
  3. No self-links. No links across workspaces (the rail dims and shakes those).
  4. No loops of leaders (A leads B leads C leads A). The badge turns red, the editor explains, and Save is disabled with the loop spelled out. Try it: center on Mergiraf, click Release captain in the rail. The backend needs the same check; today it only blocks the two-session case.
