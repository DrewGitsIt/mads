1 Starting it, and while it runs

A A toolbar button that becomes a progress pill chosen

  • Idle: “Agent Review” at the toolbar's right end with the review glyph, and a ▾ for scope (since last review / whole session).
  • Running: the button turns into a pill: grey spinner, one cell per bundle, the clock. Click → popover with stages, the current bundle and Stop. No special colour; you started it, you know it's running.

2 Findings in the diff: the inline annotation done state

A Inline annotation anchored to the line range chosen · hero

  • A coloured gutter rule marks the range; the annotation sits under the range's last line with the reviewer's full explanation, then the same Accept / Reject / Edit controls and states as the conversation checklist. Try them: the list badge and the toolbar follow.
  • One record. The footer line says so: accepting here shows as accepted in the conversation card, and the other way round. Edits keep the reviewer's original one click away.
  • Inline vs Side by side (the DiffViewer's existing chips): inline, the annotation spans the full width under the line. Side by side, it spans the modified side only; the original side gets a hatched spacer of the same height so the two sides stay aligned. Monaco forces inline below 900px, which is fine: inline is the readable layout for annotations anyway.
  • Findings on a deleted line (original side only) anchor to the nearest modified line, with "on removed line 215" in the header.
  • n / N step through findings across files, like j/k does for files.
+ The finding and its code are read together; no eye travel.
+ Same controls in both places, so there's one thing to learn.
− A long body (or an open edit box) pushes the rest of the diff down.
Monaco: annotations are view zones on the modified editor. Side by side needs a matching spacer zone on the original editor (Monaco won't add one), re-measured whenever the annotation changes height (expand, textarea resize). A textarea inside a view zone also has to stop Monaco's keybindings from eating keystrokes.

Collapsed unchanged regions

  • The real DiffViewer has hideUnchangedRegions on (3 context lines, minimum 5 to collapse). Reviewers often point at unchanged code the change made wrong. Here the P2's lines 86–90 (the lock) are untouched; the change is the Sync() at 101.
  • Scrolled to it yourself: the collapsed bar carries a badge, “1 finding hidden — Reveal”, with the finding's priority. Nothing else moves.
  • Arrived via the finding (n/N, the list badge, Open in diff from the conversation): that region auto-reveals the finding's range plus 3 context lines and scrolls to it; the rest stays collapsed.
+ Collapsing stays on, so the diff stays short, but a finding is never silently hidden.
To check: Monaco's hidden-region API is thin. A partial reveal of a range inside a hidden region may need our own view-zone badge on the collapsed bar and a programmatic reveal; that needs a spike.

3 Coverage per file, stale findings, one root per repo snapshot.go selected (the stale one)

A Folder tree, one root per repo, a coverage column chosen

  • Roots: every repo the agent touched is its own root, named by the repo, with its path: mads (marked as the session folder), tao. Paths that aren't in any repo (/tmp, ~/.config) go under one Other files root. No more single “Outside the session folder” bucket.
  • Because the backend keeps a shadow baseline per repo root, tao's file has real line counts and a real diff, and its finding opens in the diff like any other.
  • Coverage column: every changed file ends in exactly one state: a priority badge (findings; ✓ / ✎ after it when accepted / edited), ✓ reviewed clean, – skipped (reason inline), ◌ not reached. Each root header totals its own.
  • Stale: dashed badge in the list; in the diff a dashed annotation saying what changed, with Accept and Edit disabled and Re-check this file (re-reviews only that file against the current code). Reject still works.
+ Coverage is visible without a filter, in the view people already use for “where”.
+ The cross-repo finding is obvious, and gets a real diff.
Slot: ChangedFile.outside (a boolean) and folderTree.ts's OUTSIDE_ROOT become a root id + label per file (root: "tao", root_path), and the Compare-to baselines are per root: “Base branch” means a different branch in each repo.
