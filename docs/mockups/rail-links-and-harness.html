The count moves onto the trunk. LEADER · 3 becomes a 15px numeral sitting where the trunk begins. It is the same fact, costing a glyph instead of a pill, and it sits on the thing it is counting.

The marching dashes. Running live in this column — the straight runs between cards are a repeating linear-gradient rather than a border, because a border's dash offset cannot animate; every run shares one keyframe, so they move together. The rounded elbows stay still and read as the joints. prefers-reduced-motion freezes it.

What would drive it, honestly. There is no "cross-session message in flight" signal on the shared bus today. Digest delivery happens server-side and the rail never hears about it. Two options:

DriverHonest claimCost
Derived — pulse ~2s whenever a subject's agent_state transitions"the linked session just did something" — true, observed, already on the control planeNone. Pure UI.
Real — a link.digest envelope when a digest is actually injected"a digest crossed this link just now"New event type + a Data Service that knows it. See sse-bus-unknown-type: one type the running Data Service doesn't know kills the whole UI bus, so this needs the usual rollout care.

I would start derived. It animates the moment the thing you actually care about happens, it cannot lie about a delivery it did not witness, and it costs nothing to remove if the real event lands later.

The structural win, independent of which option you pick. Today's elbow is drawn by the child, reaching upward with top:-16px — a number tuned for a nominal one-line parent, as the live comment on .nestedRow::before admits outright. The moment a parent grows a two-line title, a summary teaser or a context line, the elbow stops reaching it. You can see it failing in the first column above.

The version here never reaches across a box it does not own. One trunk spans the subject stack (.subs::before, top:-5px; bottom:8px — its own container), and each subject taps it with a 10px tick at top:18px. Eighteen is not a guess: it is the status dot's centre, fixed by the title row's own box (8px padding + 1px border + 5px dot margin + half of 8px dot). Every other number is a container edge. Nothing measures a sibling, so no row height can break it. The chain also terminates where it should: only a row with another below it continues the trunk past its own tick, so a lone subject gets an elbow and nothing dangling underneath.

The structural change in SessionRail.tsx is small: RailRowGroup already renders the holder and its subjects together, so the subjects just need a wrapping <div>. That is also what finally lets the group carry a state — .live, the pulse — which no amount of per-child ::before could.

The cwd half needs a backend change first and then still shows nothing on your rail

I checked the live records before mocking this, and the directory is not there to show:

FactEvidence
Every session on this machine has cwd: "."All 20 records from GET /sessions. Not some — all.
Nothing can set itrunner.Options.Cwd comes from the session service's -cwd flag; services/router/main.go:189 builds the child argv and never passes one. Default is "." (runner.go:329).
So sess.Cwd = cwd stores the literal dotrunner.go:445 — "the resolved working dir the agent runs in". It is unresolved.
The real dir is knowableEvery live bin/session and every claude child reads /home/drew/repo/mads in /proc/<pid>/cwd. They inherit the Router's.
For an isolated session the dir is useless anyway~/.mads/worktrees/ses_7f373f2558686f50 — the terminal dir is the session id. The branch is the readable form of the same fact, which is why railLabelsFor already drops cwd when it is the worktree.

The fix is small and worth doing on its own merits: resolve "." with os.Getwd() in Start, before sess.Cwd = cwd. Not an inference — the provider child literally inherits that directory, so the record would be stating a fact it currently guesses at. It also fixes #3 at the root rather than at the tooltip.

And then, honestly: the label will be blank on every session you have, because they all run in the workspace's primary repo and railLabelsFor correctly suppresses a cwd that is the primary repo. It starts earning its slot the first time you run a session outside ~/repo/mads. That is the right behaviour — I just don't want to hand you a label that looks broken because it is working.

One trap in that suppression. samePath compares strings, and your workspace stores its repo as ~/repo/mads while a resolved cwd would be /home/drew/repo/mads. Without tilde expansion the two stop matching and every card gains a redundant mads label — the exact noise this is meant to avoid.

#3  Directory: . confirmed bug railLabels.ts:194

Two layers, and both are worth fixing.

The proximate bug

The card and the tooltip read the same field through different rules. railLabelsFor runs it through isLocation(), which exists precisely to reject "." — its comment says "a bare '.' on the context line is junk, not a location". railTooltip never got the guard:

...line("Directory", session.cwd ? displayPath(session.cwd) : undefined)

A one-line fix, and it removes the junk from all 20 cards immediately.

The cause

The guard only ever existed because the field is empty of meaning, not because dots are ugly. Fixing the tooltip alone trades a wrong line for a missing one — the hover still cannot answer "where is this running", for any session, ever.

Resolving "." server-side (above) is what makes the line worth printing. Then the guard stops firing because there is a real path, not because we taught the UI to look away.

Order: ship the guard now so the tooltip stops lying; land the resolution with #2, since that is the thing that needs the data.
