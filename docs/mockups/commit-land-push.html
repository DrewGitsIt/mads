The failed repo is selected and shows git's output; the button becomes “Commit 1 repo”.
  • “Changed by someone else”: files that differ in this repo but weren't changed by this session's tools. They start unchecked, but you can commit them. When mads knows who did it, the row names the other session; otherwise “not by a mads session” (you, an editor, a script).
  • The left list is the order you'd go in: repos with files to commit, then “Not in a repo” last. Each dot shows ready (green), needs a message (amber), nothing selected (grey), failed (red).
  • Moving a file: the repo items on the left are the drop targets. Dropping one switches to that repo and opens the folder picker (your “after the drop” from v1) at the top of its pane. Move to… does the same through a repo menu instead of dragging.
  • After the move the file sits in that repo's “Changed by this session” group, checked, and mads adds a line to the conversation with its new path so the agent doesn't keep using the old one.

G3 · Totals + status chip. The totals, the state in words and the next step are one joined control.
  • Says the state in words (“9 uncommitted”, “3 commits to land”, “committed and pushed”), so the end state is visible, not just an absent button.
  • Clearly one thing: these totals, this state, this action.
  • The widest of the three; at narrow widths the state text would drop first.
  • Turns the plain totals into part of a control, a bigger change to the existing row than G1.
In all three: the main half is the next step and does what the dock's button does (Commit opens the §1 dialog; Land and Push run with their confirm). ▾ opens §3's path popover, since there's no ⎇ segment in this tab. The counts come from the session's work state, not the Compare to choice: switching to main changes the totals but not “Commit 9”.

5 · Open questions

  1. Filters. The dialog ignores Changes' current tier, turn, search and baseline and takes everything uncommitted (it says so in the subtitle). OK, or carry the filter over as the starting checkboxes?
  2. Which push. Before Land, Push sends the session branch (for a PR). After Land, or in place, it sends the base branch from your checkout. Both in v1?
  3. Confirming a push. Every time, or only for the repo's default branch?
  4. Land and Push across repos. Same as Commit: one dialog, the repo list on the left?
  5. “Changed by someone else” at Land. Land refuses while the worktree has uncommitted files. Should the refusal open this dialog with those files shown, so you can commit them (or not) in one place?
