ba backend-architect claude-opus-4.6 · claude-code

Starting with the schema. Three requirements drive it: monotonic cursor (seq), indexed filtered reads (session + type), and same-transaction appends with state mutations — the outbox guarantee.

pkg/datasvc/schema.sqlsqlite
CREATE TABLE events (
  seq        INTEGER PRIMARY KEY AUTOINCREMENT,
  ts         TEXT NOT NULL,
  type       TEXT NOT NULL,   -- 'task.created', 'stage.completed', ...
  session_id TEXT,            -- nullable: system-level events
  task_id    TEXT,
  actor      TEXT NOT NULL,
  payload    TEXT NOT NULL    -- JSON
);
CREATE INDEX idx_events_session ON events(session_id, seq);
CREATE INDEX idx_events_type    ON events(type, seq);
  • AUTOINCREMENT (not bare rowid) so seq never reuses values after deletes — cursors stay safe.
  • Append happens inside the caller's transaction via AppendEvent(tx, …) — state and announcement can't disagree.
  • No separate metrics table: dashboards query this log (§8).

Patterns

        
Execution was healthy overall — 8 of 10 tasks completed first-pass, and the event-log decomposition held up (one merge conflict, quickly resolved). The two failures share a shape: work was judged in isolation. The reviewer passed evt-05's attempt 1 without checking the contract its dependents consume, and two parallel tasks silently shared a file. Your observation about cross-component contracts is confirmed by run #3's loop-back; the transcript shows the reviewer never opened the dependent task's scope.


        

          

            prompt-engineering
            Reviewer misses cross-component contracts
            
          

          
Evidence
evt-05 looped in run #3: review passed attempt 1 although envelope validation contradicted the append path's assumptions; the contradiction surfaced only at verify. Reviewer transcript never references evt-01's scope.

          
Root cause
The Code Reviewer prompt evaluates each task's diff in isolation — nothing instructs it to check interfaces consumed by dependent tasks.

          
Suggested action
Add to the Code Reviewer system agent: "For each interface this diff exports, find dependent tasks that consume it and verify the contract holds."

          
        


        

          

            task-decomposition
            Parallel tasks shared a file and merged with conflicts
            
          

          
Evidence
evt-01 and evt-05 both modified pkg/datasvc/schema.go; the merge stage blocked once before manual resolution (run #3, 12:52).

          
Root cause
Decomposition split the envelope and the table into parallel tasks whose scopes list the same file — hidden coupling the dependency graph didn't encode (§17: conflicts are feedback).

          
Suggested action
Synthesizer guidance: when two draft tasks name the same file in scope, propose a dependency between them or a merge into one task.

        


        

          

            pipeline-template
            Verify stage re-runs the full suite per task
            
          

          
Evidence
verify averaged 4m per task in run #3; ~80% of wall time was test packages untouched by the task's diff.

          
Root cause
The default template's verify stage runs `make test` globally for every task.

          
Suggested action
Scope verify to packages in the task's diff, and add one full-suite gate stage at the end of the run.
