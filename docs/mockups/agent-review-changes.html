Agent Review: the Changes tab side

The Changes tab is where findings meet the diff they're about. The button here and /review in the conversation start the same job. Same review as agent-review-conversation.html:

  • Scope since last review, turns 12–18 (shaded on the turn strip): 13 files, 12 in the session folder ~/repo/mads, one in ~/repo/tao (outside it).
  • Reviewer reviewer · goose · qwen3.8-coder-nothink, 10m limit → partial: 8 reviewed, 3 skipped (lockfile, generated snapshot, scratch debug_dump.go), 2 not reached (review/verify.go, review/merge.go).
  • Findings 1 P1 · 3 P2 · 1 P3. The snapshot.go P2 is stale: the agent edited that file in turn 19, after the snapshot.

1 Starting it, and while it runs use the state switch on each option

A A toolbar button that becomes a progress pill

  • Idle: “◎ Agent Review” at the toolbar's right end, with a ▾ for scope (since last review / whole session). The last review's result is a quiet note next to it.
  • Running: the button turns into a pill: spinner, a cell per bundle, the clock. Click → popover with stages, the current file and Stop.
  • Done: the pill shows the counts and partial flag; click → the same popover with Send / filter actions. Rows get a priority badge.
+ Smallest footprint: no new row; the list and diff keep every pixel.
+ One control, one place, through the whole lifecycle.
− The toolbar already wraps on narrow widths (Compare to + totals + Full-width); the pill is the first thing to get squeezed.
− Coverage and the verdict hide in a popover.

B A review strip above the file list

  • The button stays a plain button. Once a review exists, a full-width strip sits between the turn strip and the body.
  • Running: reviewer, stage, bundle bar, current file, clock / limit, Stop.
  • Done: verdict, counts, coverage bar, partial notice with “Review the rest”, and the bulk actions. ✕ hides the strip but keeps the badges.
+ Room for the verdict, coverage and bulk send without a popover.
+ Reads as being about the whole change set, which it is.
− ~36px of permanent height in a tab that's already toolbar + turn strip + context line.
Slot: ChangesTab has no band between TurnStrip and .body today; it's a straightforward insert, but it's new layout.

C Per-file glyphs that fill in as bundles finish

  • The progress is the file list: each row gets a review column. · queued, in the current bundle, ✓ clean, a priority badge when it has findings, – skipped.
  • The toolbar keeps only a small “Reviewing 3/7” label and Stop. Group headers show their own tally.
+ You can see exactly what's been looked at, and start reading early findings while the rest run.
+ After it's done, the column simply stays: coverage for free (see section 3).
− No overall verdict or bulk action anywhere visible; needs A's popover or B's strip alongside.
− Another column in rows that are already tight at 340px.

2 Findings in the list and the diff done state, job.go selected

A Inline annotation anchored to the line range

  • List rows get one badge for their highest open priority (+n when there are more).
  • In the diff a coloured gutter rule marks the range, and the finding sits right under its last line, GitHub-review style: title, body, confidence, verified, cited rule, actions.
  • n / N step through findings across files, like j/k does for files.
+ The finding and its code are read together; no eye travel.
+ Familiar from every code-review tool.
− A long body pushes the rest of the diff down.
Slot: DiffViewer is Monaco; inline cards mean view zones + glyph-margin decorations, re-laid out on resize. Doable, but the most custom option here.

B A findings panel beside the diff

  • A 300px column to the right of the diff: This file / All (5). Clicking a card scrolls the diff to its range and highlights it; the diff carries only a gutter rule.
  • “All” makes the panel a review queue you can work through without touching the file list.
+ No reflow of the diff; Monaco needs only decorations.
+ Bulk select + send fits naturally at the panel's foot.
− Three columns: on a 13" laptop the diff drops to ~470px; the panel needs to collapse.
− Eye travels between the line and the card.

C Group by: Review, findings as list rows

  • A sixth grouping, Review, nests findings under their file in the list. Selecting a finding opens the file's diff scrolled to the range, with the finding pinned in a header above the diff (where the plug-in summary sits in changes-v2).
  • Other groupings keep just the row badge.
+ Uses the list as the queue: j/k walks findings, the diff stays clean.
+ The header slot already exists (plug-in summary).
− Finding text is truncated in a 340px list; the full body is only in the header.
− Only one finding visible at a time in the diff.

3 Coverage per file, stale findings, multiple roots snapshot.go selected (the stale one)

A Folder tree with named roots and a coverage column

  • Every changed file ends in exactly one state, shown in the right column: badge (findings), ✓ reviewed clean, – skipped + reason on hover, ◌ not reached.
  • Roots are named per repo (mads, tao) instead of today's single “Outside the session folder”; non-repo paths like /tmp still go to Outside.
  • Stale: dashed badge; in the diff, a dashed annotation that says what changed and offers Re-check (re-review this file only) or Show current diff.
+ Coverage is visible without a filter, in the view people already use for “where”.
+ Named roots make the cross-repo finding obvious.
Tension: outside files come through as counts_unknown (no line counts, “—”, see demoChangeSet.ts). If there's no baseline for them either, “Open in diff” on the tao finding can only show the file at the snapshot. Named roots imply per-root baselines (tao is its own git repo).

B Group by: Review, by outcome

  • Groups are the outcomes: Findings, Stale, Not reached (with “Review these 2”), Reviewed, clean, Skipped (reason per row). Clean and Skipped start collapsed and dimmed, like Generated/Scratch tiers.
  • Root is a small chip on the row (tao) rather than a level of grouping.
+ Coverage is an accounting you can check at a glance: the counts add up to 13.
+ Stale gets its own group, so it's never mistaken for an open finding.
− Loses folder/tier context while you're in it.
− Collides with 2C if both use the “Review” grouping name; pick one meaning.

C Filter chips over the existing tiers + a coverage ledger

  • Keep whatever grouping you're in; the review adds filter chips (Findings · Stale · Not reached · Skipped) above the list, and a small per-root ledger at the list's foot.
  • Rows carry the glyph column from 1C and a root chip when not in the session folder.
+ Least disruptive: Tier stays the backbone, as changes-v2 decided.
+ The ledger answers “did it look at everything in tao?” directly.
− Two new bits of chrome (chips + ledger) in the list column.
− Filters are easy to leave on and forget.
