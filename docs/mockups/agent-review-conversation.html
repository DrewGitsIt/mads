2 The finished review: a checklist you decide on verdict, counts, coverage, every finding in full

This is live: expand rows, Accept, Reject (with an optional reason), Edit (your text replaces the reviewer's), Undo. The send button and section 3's message follow along. Try Re-check this file on the stale row.

B Full checklist in the card chosen accept / reject / edit, then send

How it behaves

  • Every finding is a row: priority, title, file:line, cited rule, verified, and its state. Click a row to expand the reviewer's full explanation (why it's a problem, the evidence with file/line/function refs, a suggested fix). The first row starts expanded.
  • Accept takes the reviewer's text as is. Edit opens a textarea prefilled with it; your text replaces it, and the original stays one click away. Reject takes an optional short reason, kept with the review (for tuning the reviewer), never sent.
  • States: open accepted edited by you rejected stale. After sending: sent.
  • Stale: Accept and Edit are disabled (the lines no longer match the code); Re-check this file re-runs the reviewer on just that file. Reject still works.
  • Send N to agent counts accepted + edited. No confidence scores anywhere; priority does the ranking.
  • Each finding is one record shared with the Changes tab's inline annotations. Accepting here shows as accepted there, and the other way round.

+ Everything decidable without leaving the conversation; bulk send is explicit about exactly what goes, in whose words.

− Grows with the finding count. Past ~8 findings, fold the P3s behind "+ n more".
